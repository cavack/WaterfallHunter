# Dependency-aware development graph

```text
Wave 0: canonical hashing
  ├─ Runtime Fingerprint
  └─ Golden Corpus tooling
       └─ Artifact provenance
            └─ CI/runtime artifact parity

Wave 1: contracts → migrations/readiness → unified metadata
  → cohort purity → probability cleanup/freshness/strict filters

Wave 2: typed API
  ├─ Dashboard Decision Terminal + SSE retention/fallback
  ├─ Telegram persistent delivery platform
  └─ Observability expansion

Wave 3: ExecutionPlan/ExecutionRisk → leverage/PnL/ISOLATED state
  → deterministic portfolio simulator → Backtest Lab

Wave 4: Lifecycle V2 shadow + reassessment/anomalies
  → MarketContext → asynchronous AI advisory → discovery priority

Wave 5: clean strict dataset → replay → walk-forward/holdout/OOS
  → calibrated probability/ETA/lifecycle promotion decision

Wave 6: adversarial/security/regression → shadow soak → certification
```

Shared schema, canonical contracts, lifecycle interfaces, and signal persistence are serialized work. Frontend, notifications, and observability may proceed in parallel only after typed domain interfaces settle. Model-affecting promotion is blocked until the dual Golden Corpora and scientific gates exist.
