# Support

WaterfallHunter is an actively developed research system, not a hosted support service and not financial advice.

## Where to report something

- **Reproducible defect:** open a Bug Report issue and include exact revision, environment, reproduction, expected behavior, and observed evidence.
- **Change or research proposal:** open a Change Request issue and state the problem, scope, expected evidence, and safety impact.
- **Security vulnerability:** use GitHub Private Vulnerability Reporting as described in [SECURITY.md](SECURITY.md). Do not open a public issue.
- **Production incident:** use the operator procedures in [docs/OPERATIONS.md](docs/OPERATIONS.md) and [docs/TROUBLESHOOTING.md](docs/TROUBLESHOOTING.md).

Questions that depend on a specific runtime should include the exact commit SHA and whether the observation came from local development, CI, replay, or Production. Missing evidence should be reported as `UNAVAILABLE`, not inferred as success.
